## Your unit
Build `money_bridge.executor`:
- **Process:** `python -m money_bridge.executor --data-dir D` and an exported `run(argv)`; serves HTTP over the Unix socket `D/run/exec.sock` (Uvicorn UDS, socket mode 0660) with a peer-credential check (`SO_PEERCRED` on Linux, `LOCAL_PEERCRED`/`getpeereid` on macOS) against `D/executor/config.toml` (`core_uids`, `owner_uids`): core routes accept only core uids, owner routes only owner uids, anything else is rejected and logged. Export an `ExecutorClient` (httpx over a UDS transport) that the Core will use.
- **Journal:** SQLCipher (`sqlcipher3`) at `D/executor/journal.db`, its own key, WAL, numbered migrations; tables `intent`, `transition` (append-only), `approval`, `attempt`, `reservation`, `policy_revision`, `agent_grant`, `approver`, `epoch`, plus an `outbox` of action-state events the Core can page through (`GET /v1/events?after=`).
- **Core routes:** prepare (agent id, proposal, request key) → intent status; status; list (own intents); abandon; capabilities (enabled providers/operations with reasons, including high-impact actions — cancel subscription, dispute, add beneficiary, virtual card, account settings — reported `disabled` with reason `not_qualified`); events page. No execute route, no mark-approved route.
- **Owner routes:** set policy (per-action and rolling-24h ceilings per source account + currency, max pending queue, proposal rate limit; reductions immediate, every change a new policy revision), enroll approver (pin credential id, public key, RP ID, origin for an approval adapter), sync agent grants (which `propose:*` kinds and accounts each agent id may use; revocation takes effect before the call returns), enable/disable a provider route, recover (reconcile outstanding attempts and open a new epoch).
- **Intents (SPEC §8):** proposals for `transfer`, `payment`, `trade` (limit orders only) and `purchase`; resolve and freeze into canonical JSON with digest; request-key dedupe (same key + same canonical proposal → same intent; same key + different → `conflict`); expiry; pending-queue limit; lifecycle `proposed → frozen → awaiting_approval → approved → submitting → accepted → settled` with terminal `denied`, `expired`, `abandoned`, `rejected` and `outcome_unknown → reconciling`.
- **Approval adapters** (seam `request(frozen) -> ApprovalRef`, `inspect(ref) -> ApprovalEvidence`): `cosignet` (HTTP client for Cosignet's REST API, private links, `public: false`, approval card only: action, amount/currency or trade bounds, payee/instrument, account display name, environment, expiry, intent id, digest — never balances, history, account numbers or rationale), and `fake` = the same client pointed at `tests/fakes/fake_approval` (test profile only). Evidence is verified locally with py_webauthn (`webauthn` package) against the **pinned** approver credential: signature, RP ID, origin, user verification, challenge bound to the intent digest and a nonce, expiry. An `approved: true` flag alone is never enough. A `link_native` adapter is a later unit; leave the seam ready.
- **Execution adapters** (seam `prepare(frozen) -> ProviderRequest`, `submit(request, attempt) -> SubmitOutcome`, `lookup(attempt) -> LookupOutcome`): `faulty_broker` (test profile only) speaking HTTP to `tests/fakes/faulty_broker`. Alpaca MCP, Link CLI and Teller payments adapters are later units.
- **Submission:** one journal transaction rechecks grant, policy version, expiry and epoch, reserves limits (gross exposure incl. fees, pending, unknown and open orders), consumes the approval, creates the attempt with a stable client id, marks `submitting`, commits; then submits the frozen arguments. Timeout/5xx/crash after send → `outcome_unknown`, reservation kept; reconciliation looks up by client id; an empty or negative lookup never authorizes a resend; at most the provider-contracted retries reuse the same client id and identical arguments. Crash points via `MONEYBRIDGE_TEST_CRASH_AT` (test profile only): `submit.before_send`, `submit.after_send`, `submit.after_response`.
- **Restore safety:** a journal marked restored (or whose epoch does not match `D/executor/epoch`) refuses submissions (`read_only`) until owner `recover` reconciles and opens a new epoch.
- **Fakes (real processes):** `python -m tests.fakes.fake_approval --port N --state DIR`: Cosignet-shaped API with a software WebAuthn authenticator (ES256), control endpoint to approve, deny, let expire, replay an old assertion, or sign with an unpinned credential. `python -m tests.fakes.faulty_broker --port N --state DIR`: accepts orders/payments with client ids into an independent effect log, control endpoint to execute-then-drop-response, delay lookup visibility, return 5xx, expire idempotency.
